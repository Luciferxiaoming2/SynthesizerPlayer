# Audio Forge / Synthesizer Player 需求文档（PRD）

版本：2026-05-25  
形态：Python 桌面应用，当前以 PyQt6 + QML 单窗口界面交付  
目标平台：Windows 10 / Windows 11，优先适配 Intel 轻薄本与无独立显卡设备

## 1. 产品定位

Audio Forge 是一款面向普通用户和轻量创作者的本地音乐处理桌面应用。用户只需要导入一首常见格式的歌曲，软件应自动完成歌曲工程化管理、人声/伴奏分离、歌词加载或识别、滚动歌词播放、跑调效果试听、局部改词唱试听等操作。

产品优先级不是做专业 DAW，而是把复杂音频处理流程封装成普通用户能理解的中文界面：导入歌曲、等待处理、播放试听、调整参数、必要时导出或继续编辑。

## 2. 用户与使用场景

### 2.1 目标用户

- 不懂音频工程术语的普通用户。
- 想快速制作跑调、改词、翻唱试听效果的内容创作者。
- 没有 NVIDIA 显卡、不会配置 Python/AI 模型环境的轻薄本用户。
- 后续交付对象可能只会双击启动程序，不会手动安装依赖。

### 2.2 典型场景

- 用户导入一首 MP3，软件自动分离人声和伴奏，并在歌曲库中保留该工程。
- 用户播放歌曲时查看同步滚动歌词，中文歌词应显示简体中文，英文歌曲应保留英文。
- 用户拖动“跑调程度”，立即试听人声自然跑调效果，伴奏保持同步。
- 用户双击某句歌词，在右侧输入新词，生成轻量试听版改词唱片段。
- 用户删除歌曲时，软件弹出确认框，并同步删除 `save` 下对应工程文件。
- 用户再次启动应用时，自动扫描 `save` 文件夹并加载第一首可用歌曲。

## 3. 范围说明

### 3.1 当前版本范围

- 本地歌曲导入与工程缓存。
- 多格式音频兼容和标准化。
- Demucs 等本地分离流程接入。
- 双轨播放：人声、伴奏、主输出音量控制。
- 歌词文件加载、ASR 生成、简体中文规范化、滚动显示。
- 跑调程度调节和缓存式处理。
- 右侧 AI 改词唱工作舱的轻量试听流程。
- 删除、清空、打开文件夹、扫描 `save` 等歌曲库管理。
- 便携版打包，开发阶段可依赖本机 Python 环境，最终交付需内置运行环境。

### 3.2 暂缓或实验范围

- 高质量商用级改词唱模型。
- VST 插件宿主完整能力。
- 云端模型推理服务。
- 多轨专业编辑、频谱级手工修音、完整 DAW 工作流。
- macOS / Linux 正式交付。

暂缓功能可以在界面中保留入口，但必须置灰、说明条件，或收纳到设置中，不能让用户误以为已经完整可用。

## 4. 功能需求

### FR-01 启动与歌曲库加载

- 应用启动后必须自动定位程序同级或配置指定的 `save` 文件夹。
- 如果 `save` 中存在歌曲工程，应自动扫描并加载列表。
- 如果歌曲列表不为空，应默认选中并加载第一首歌，避免用户未选择歌曲时点击播放、下一首或歌词操作导致报错。
- 如果没有歌曲，应显示中文空状态提示，引导用户导入歌曲。
- 应支持从旧版本目录迁移历史工程，迁移后歌曲相关文件仍应归入 `save`。

验收标准：

- 双击便携版启动后，不需要用户重复导入已有歌曲。
- `save` 中有一首歌时，主界面能直接显示该歌信息和可用操作。
- `save` 为空时，界面不报错，显示导入提示。

### FR-02 歌曲导入与工程创建

- 用户可以导入单个音乐文件。
- 支持常见音频格式：MP3、WAV、FLAC、M4A、AAC、OGG；后续可扩展 WMA、AIFF 等格式。
- 导入时应在 `save/<歌曲名>/` 下创建独立工程目录。
- 工程目录至少包含：
  - 原始或标准化音频文件。
  - `project.json` 工程描述。
  - 分离后的人声/伴奏文件。
  - 歌词文件。
  - 跑调缓存、改词试听缓存等派生文件。
- 导入同名歌曲时应自动生成不冲突目录，例如 `<歌曲名>_2`。
- 导入过程较慢时必须显示中文进度或状态提示。
- 导入失败时必须显示用户能理解的中文原因，并保留可恢复状态。

验收标准：

- 导入一首 MP3 后，左侧歌曲列表立即新增该歌曲，不需要重启或手动刷新才能看到。
- 导入过程中界面不卡死，用户能看到“正在处理/正在分离/正在生成歌词”等状态。
- 所有导入产生的业务文件都位于 `save` 下。

### FR-03 人声与伴奏分离

- 系统应在导入后自动或按需调用本地分离后端。
- 当前优先使用 Demucs 方案，允许未来切换 UVR、Spleeter 或更轻量后端。
- 分离结果应保存为独立的人声轨与伴奏轨。
- 播放时人声与伴奏必须时间对齐。
- 如果分离失败，应允许用户播放原曲或重试，不应让工程不可用。
- 分离状态应写入工程描述，避免每次启动重复分离。

验收标准：

- 关闭人声音量时，理论上应主要听到伴奏。
- 关闭伴奏音量时，理论上应主要听到人声。
- 分离完成后再次启动应用，不应重复执行耗时分离。

### FR-04 播放控制

- 应提供播放、暂停、停止、上一首、下一首、播放模式切换。
- 播放模式至少包括：顺序播放、单曲循环、列表循环。
- 用户快速切换歌曲或快速点击播放按钮时，应用应进行节流和状态保护，避免卡死。
- 进度条可拖动定位播放位置。
- 播放、暂停图标应使用清晰标准符号，暂停符号为纯色两条竖杠。

验收标准：

- 连续点击下一首、播放、暂停不会造成界面永久无响应。
- 单曲循环和列表循环按预期生效。
- 拖动进度条后歌词和播放位置同步更新。

### FR-05 音量与混音控制

- 底部控制区应提供人声音量、伴奏音量、主输出音量。
- 滑条右上角百分比必须与滑条当前值同步。
- 应用启动时百分比显示必须与默认滑条值一致。
- 用户调整人声或伴奏音量时，应实时影响播放结果。
- 滑条视觉规则：已拉过部分为白色，未拉部分为深灰。

验收标准：

- 人声音量设为 0% 时，不应继续听到明显的人声轨输出，分离残留除外。
- 伴奏音量设为 0% 时，不应继续听到明显伴奏轨输出。
- 所有相关数值显示与滑条位置一致。

### FR-06 歌词加载、识别与规范化

- 导入歌曲时应优先查找同名 `.lrc`、`.srt` 或工程内已有歌词。
- 没有歌词时，应提示用户是否生成歌词。
- 用户点击生成歌词后，应使用本地 ASR 后端生成带时间戳歌词。
- 当前优先支持 faster-whisper，本地模型默认从 `plugins/models/faster-whisper/` 查找。
- 中文歌曲识别结果应尽可能转为简体中文；英文歌曲保留英文。
- 不应把模型提示词、系统说明、乱码文本写入歌词。
- 纯音乐或识别不到有效文本时，应显示“纯音乐或暂无歌词”。
- 歌词生成过程必须显示进度或状态，不能让界面像卡死。

验收标准：

- 中文歌曲生成歌词后，界面显示简体中文。
- 英文歌曲生成歌词后，界面显示英文。
- 没有歌词时会先弹窗询问是否生成，而不是静默失败。

### FR-07 滚动歌词舞台

- 中间舞台显示当前歌曲歌词，并随播放进度自动滚动。
- 当前行应突出显示，并显示该句时间，时间位于当前行最右侧。
- 当前句内可显示逐字或逐词进度：中文按字，英文按单词。
- 需求方向为“已唱过的字/词更大，未唱部分更小”。
- 长歌词超过可视区域时，左侧应向左滚动或裁切隐藏，避免遮挡右侧时间。
- 已唱完的非当前行应回到较弱视觉状态，不应长期占用过大空间。
- 用户点击或双击某句歌词时，该句被选中，并触发右侧改词唱工作舱。

验收标准：

- 播放时歌词自动滚动到当前行。
- 长句不会遮挡右侧时间。
- 当前行的字词进度对中文和英文都可读。

### FR-08 歌词对齐校正

- 应提供歌词整体偏移校正入口。
- 快捷按钮包括：`-0.5s`、`-0.1s`、`0s`、`+0.1s`、`+0.5s`。
- `0s` 表示不进行偏移，是默认状态。
- 调整后歌词显示应立即根据新偏移刷新。

验收标准：

- 点击 `+0.1s` 后，歌词相对播放时间延后显示。
- 点击 `0s` 后恢复不偏移。

### FR-09 跑调程度调节

- 应提供“跑调程度”滑条。
- 用户拖动跑调程度时，应尽量在当前播放中体现效果。
- 处理方式应优先避免“两个人同时唱”、原唱盖过处理声、明显炸麦、音色严重失真等问题。
- 跑调效果应尽可能保留原人声音色，只改变音准漂移和自然不稳定感。
- 对于需要离线渲染或缓存的处理，界面应给出轻量状态提示，但调整跑调程度时底部不显示大面积加载条。
- 跑调缓存应保存在当前歌曲工程目录下，不得写到 `save` 之外。
- 算法应兼容中文、英文及其他语言歌曲，不应依赖具体歌词语言。

验收标准：

- 跑调程度从 0 增大后，用户能听到明显但自然的音准变化。
- 不出现原始人声和处理人声同时播放造成的重音感。
- 拖动滑条不会导致程序长时间卡死。

### FR-10 AI 智能改词唱工作舱

- 用户点击或双击中间某句歌词后，右侧栏切换为“AI 智能改唱工作舱”。
- 工作舱应展示：
  - 当前选中时间段。
  - 原始歌词。
  - 新歌词输入框。
  - 当前改词唱模式。
  - 启动改唱/试听按钮。
  - 重置原词按钮。
  - 取消或返回按钮。
  - 已生成试听版本列表。
- 用户修改歌词后，点击生成应生成该句试听片段，并在播放到该句时替换或叠加到正确位置。
- 当前轻量本机方案必须明确提示“试听版/本机轻量版”，避免误导用户认为是高质量商用模型。
- 如果真实模型环境未就位，应给出中文条件说明。
- 重置按钮应清空当前句的新词、试听片段和右侧状态，并恢复原句播放。
- 已生成试听版本应支持选中和删除。
- 歌曲被删除或列表被清空时，改词唱状态必须同步清空。

验收标准：

- 双击歌词后右栏出现改词唱工作舱，而不是空白或错位到左上角。
- 点击重置后，右侧输入内容和试听版本清空。
- 删除歌曲后，改词唱面板不再保留已删除歌曲的信息。

### FR-11 文件与目录管理

- 所有歌曲工程、歌词、分离文件、跑调缓存、改词缓存都必须放在 `save` 文件夹下。
- 便携版根目录不应散落业务音频文件、歌词文件或中间产物。
- 左侧应提供：
  - 导入歌曲。
  - 扫描 `save`。
  - 打开 `save` 文件夹。
  - 打开当前歌曲目录。
  - 删除选中。
  - 清空列表。
- 删除选中和清空列表必须弹出确认框。
- 用户确认后才删除磁盘文件。
- 如果被删除歌曲正在播放，应停止当前播放，并自动切换到下一首可用歌曲或显示空状态。

验收标准：

- 删除选中歌曲后，`save` 下对应工程目录被删除。
- 清空列表后，`save` 中歌曲工程被删除，界面列表同步清空。
- 删除过程不会删除 `plugins`、`_internal`、程序 exe、README 等非业务目录。

### FR-12 设置与未实现功能管理

- 不常用功能应放入右上角设置入口，避免主界面拥挤。
- 与左侧重复的导入、扫描、删除等功能不应重复出现在设置中。
- 未完成的功能按钮必须置灰或隐藏，并提供中文状态说明。
- VST、外部模型、云端后端等高级能力应以“实验/未就绪/需要配置”的方式呈现。

验收标准：

- 用户不会在主界面看到多个重复入口。
- 点击未就绪能力不会触发崩溃或无响应。

### FR-13 主题与窗口适配

- 应支持深色主题，后续支持亮色主题。
- 当前默认深色主题应保持可读性和高对比度。
- 组件应随窗口放大或缩小进行合理缩放。
- 最小窗口尺寸下，主要文本不应互相重叠，不应超出按钮或卡片。
- 右栏文字必须在卡片内换行或缩放，不得溢出方框。

验收标准：

- 在常见轻薄本分辨率下，左栏、中间歌词、右栏和底部控制区不重叠。
- 放大窗口后主要区域按比例扩展。

### FR-14 打包与便携版

- 开发阶段可以依赖本机虚拟环境。
- 最终交付必须把 Python 运行环境、必要依赖、启动脚本、插件和模型配置一起打包，用户无需手动安装 Python。
- 便携版应支持双击 `启动 Audio Forge.bat` 或 exe 运行。
- 大体积模型可先以外置目录方式交付，但必须有清晰中文说明。
- 打包后每次业务代码或 UI 修改都应重新生成便携版用于验收。

验收标准：

- 在目标机器上解压便携版后，普通用户可双击启动。
- 缺少可选模型时，核心播放、导入、歌词和跑调功能仍可用或有明确降级提示。

## 5. 非功能需求

### NFR-01 性能与响应

- 应用启动到主界面可操作的时间应尽量控制在 5 秒内；首次扫描大量歌曲可异步进行。
- 普通播放、暂停、切歌、音量调节应在 200ms 内给出界面反馈。
- 导入、分离、歌词识别、改词生成等耗时任务必须放到后台线程或独立进程。
- 耗时任务期间主界面不能永久卡死。
- 快速连续点击高成本按钮时应节流、防重入，并显示当前处理状态。

### NFR-02 稳定性

- 播放引擎、分离流程、ASR、改词生成失败时不能导致整个应用崩溃。
- 文件缺失、工程损坏、模型缺失、ffmpeg 缺失等情况必须有中文错误提示。
- 操作失败后应尽量保持上一个可播放状态。
- 对正在播放的歌曲执行删除、切换、重新导入时，必须先安全停止或释放音频资源。

### NFR-03 音频质量

- 标准播放时不得引入明显爆音、削波或断续。
- 人声与伴奏混音应避免重复叠加同一路信号。
- 跑调处理应优先保留原音色、节奏和时长。
- 改词试听版允许质量低于最终商用模型，但不能输出明显咕咕声、纯噪声或无法理解的片段作为“成功”结果。
- 对分离残留应通过提示说明“分离模型限制”，不能把残留误认为音量控制失效。

### NFR-04 兼容性

- 必须优先支持 Windows 10 / Windows 11。
- 必须优先支持无独显设备。
- 应兼容常见中文路径、空格路径和非 ASCII 文件名。
- 应支持 44.1kHz、48kHz 等常见采样率输入，并在内部统一处理。
- 应兼容中文歌曲、英文歌曲和纯音乐。

### NFR-05 可用性

- UI 文案必须以简体中文为主。
- 必须避免直接暴露用户难理解的英文术语；确需出现时应配中文解释。
- 重要状态必须明确，例如“正在分离人声”“正在生成歌词”“模型未就位”“处理失败，可重试”。
- 不可逆操作必须二次确认。
- 用户不应被要求理解 Python、虚拟环境、模型目录等技术细节才能使用核心功能。

### NFR-06 数据安全与边界

- 删除操作只能删除 `save` 下的歌曲工程或用户明确选择的业务文件。
- 不得递归删除程序目录、插件目录、内部运行库目录。
- 自动迁移旧文件时必须限制在可识别的历史业务产物范围内。
- 工程配置应尽量使用相对路径或可迁移路径，便携版移动目录后仍能识别歌曲。

### NFR-07 可维护性

- 业务逻辑、UI 绑定、音频处理、模型适配、打包脚本应保持清晰边界。
- 新增音频后端或模型后端时，应通过适配器扩展，避免把外部工具调用散落在 UI 层。
- 重要行为需要补充自动化测试，尤其是：
  - `save` 目录管理。
  - 导入工程创建。
  - 删除与清空。
  - 歌词路径生成。
  - 旧目录迁移。
- 文档和开发记录应随重要功能变更同步更新。

### NFR-08 可交付性

- 便携版根目录应保持整洁，仅包含程序、启动脚本、内部运行库、插件、模型和 `save`。
- 最终交付包大小应可解释；大模型需要可选下载或单独交付方案。
- README 必须为中文，说明启动、导入、模型放置、常见问题。
- 交付前应完成基础 smoke test：启动、导入、播放、切歌、歌词显示、删除确认。

### NFR-09 可观测性与诊断

- 关键失败应写入日志，方便定位用户机器上的问题。
- 日志应包含任务阶段、错误原因和相关文件路径。
- 日志不应记录用户隐私内容之外的无关信息，也不应上传到外部服务。
- UI 中显示给用户的错误要简洁，详细堆栈保留在日志中。

### NFR-10 授权与开源依赖

- 引入开源项目时必须确认许可证是否允许当前项目使用和分发。
- 对 Demucs、faster-whisper、Rubber Band、ffmpeg、Qt/PyQt 等依赖应记录来源和许可证注意事项。
- 商业插件或模型不能默认打包，除非确认授权允许。

## 6. 数据结构与目录约束

推荐便携版结构：

```text
AudioForgePortable_next/
  audio-forge-ui.exe
  启动 Audio Forge.bat
  README.txt
  _internal/
  plugins/
    models/
      faster-whisper/
      ffmpeg/
      rubberband/
  save/
    歌曲名/
      project.json
      original_standard.wav
      lyrics.lrc
      stems/
      cache/
      rewrite/
```

要求：

- `save/<歌曲名>/project.json` 是工程入口。
- 歌曲相关派生文件全部归属于对应歌曲目录。
- 旧版遗留文件可迁移到 `save/_legacy_root_outputs/` 或对应歌曲目录。
- 不允许在便携版根目录生成无归属业务文件。

## 7. 优先级

### P0 必须完成

- 启动加载 `save`。
- 导入单曲并创建工程。
- 播放、暂停、停止、切歌。
- 人声/伴奏音量和主输出音量。
- 歌词加载、生成、滚动、简体中文规范化。
- 跑调程度基础可用，避免双人声混音。
- 删除选中、清空列表、二次确认、同步删除文件。
- 便携版可运行。

### P1 重要增强

- 跑调自然度优化。
- 改词唱本机轻量试听。
- 歌词逐字/逐词进度。
- 亮色主题。
- 更完整的错误日志与诊断。
- 导入和分离进度细化。

### P2 后续探索

- 高质量改词唱模型接入。
- VST 宿主。
- 外部推理服务。
- 高级导出和批处理。

## 8. 验收清单

- 在便携版中双击启动，界面显示中文且无明显错位。
- `save` 中已有歌曲时自动加载第一首。
- 导入 MP3 后左侧列表立即新增歌曲。
- 导入后的分离、歌词、缓存文件都在 `save/<歌曲名>/` 下。
- 播放时歌词自动滚动，当前句时间在右侧。
- 中文歌词显示简体中文，英文歌词保留英文。
- 跑调程度调节不会出现原唱和处理声明显叠加。
- 快速点击播放/暂停/下一首不会卡死。
- 删除选中和清空列表都有确认框，确认后磁盘文件同步删除。
- 没有配置高质量改词唱模型时，右侧工作舱给出明确中文说明或使用轻量试听模式。
- 打包后 smoke test 通过。

## 9. 风险与限制

- 人声/伴奏分离质量依赖模型，某些歌曲会残留原唱或伴奏串音。
- 无独显轻薄本不适合实时运行大型改词唱模型，高质量方案可能需要外置模型包或云端后端。
- 本机 TTS 轻量改词唱只能作为试听或占位能力，不能等同于专业 AI 翻唱。
- 跑调处理需要在“明显跑调”和“保留音色”之间平衡，部分歌曲可能需要缓存或离线处理。
- PyInstaller 打包大型 AI 依赖会显著增大交付包，需要按功能拆分可选模型。
