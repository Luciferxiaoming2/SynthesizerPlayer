# 2026-05-24 UI 卡顿与自适应缩放修复

## 背景

用户反馈新版播放器界面点击几下会卡死，并希望窗口放大或缩小时，界面组件能够同步放大或缩小。

## 问题定位

- 跑调滑杆拖动时会频繁触发整首歌跑调缓冲重建，属于重计算，连续拖动容易阻塞 UI。
- 播放定时器每 100ms 推进一次时，原先复用同一个 `lyricsChanged` 信号通知当前歌词和整份歌词列表，QML 可能反复读取并重建歌词列表。
- 参考图界面第一版采用较多固定尺寸，窗口缩小时容易拥挤，放大时组件比例不跟随。

## 本次推进

- 将歌词信号拆分为：
  - `lyricLinesChanged`：只在歌词文件内容变化、重新加载歌曲、清空列表时发出。
  - `lyricPositionChanged`：只在当前歌词行、当前歌词文本或下一句变化时发出。
- `_update_lyrics()` 增加无变化短路，播放定时器不再无条件刷新歌词 UI。
- 跑调滑杆改为 280ms 合并应用，并在松手时立即应用最终值，避免拖动过程中连续重算整首音频。
- QML 主界面增加 `uiScale`，以 1480x920 为设计稿基准整体缩放；窗口放大/缩小时，顶部、左右面板、中间歌词区、底部控制台会按比例同步变化。
- 降低默认窗口高度和最小尺寸，避免小屏幕启动时过高。
