# 2026-05-23 Demucs 本地运行环境补齐

## 本次目标

继续推进 P0/P13 单曲导入自动拆解：让 Demucs 适配器不再依赖用户目录缓存和系统 PATH，而是优先使用项目本地的模型缓存与 ffmpeg 工具目录。

## 已完成

- 扩展 `core_engine/player/stem_separator.py`：
  - `DemucsSeparatorConfig.ffmpeg_dir` 现在会注入到 Demucs 子进程 `PATH`。
  - `DemucsSeparatorConfig.torch_home` 现在会注入到 Demucs 子进程 `TORCH_HOME`。
  - `segment` 和 `jobs` 配置现在会进入实际 Demucs 命令。
  - 默认改为调用 `core_engine.player.demucs_soundfile_runner`，推理仍使用开源 Demucs，wav 保存改用项目已有 `soundfile`，绕开 Windows 上 `torchaudio/torchcodec` 对 full-shared FFmpeg DLL 的依赖。
- 新增 `core_engine/player/demucs_soundfile_runner.py`：
  - 只替换 Demucs 的 wav 保存函数。
  - 非 wav 输出仍回退到 Demucs 原始保存逻辑。
- 扩展 `harness/cli_harness/import_song.py`：
  - 新增 `--demucs-ffmpeg-dir`。
  - 新增 `--demucs-torch-home`。
  - 未显式传参时，优先查找 `plugins/models/ffmpeg`，再复用旧源码目录中的 `ffmpeg/bin`。
- 扩展 `ui/main_window.py`：
  - GUI 选择 `demucs` 后端时，会自动尝试使用 `plugins/models/ffmpeg`、旧源码 `ffmpeg/bin` 和 `plugins/models/torch`。
- 扩展 `tests/test_song_importer.py`：
  - 覆盖 Demucs 本地运行环境注入。
  - 更新 Demucs 命令构造断言，覆盖默认 `--segment 7`。
  - 覆盖 soundfile runner 可直接写出 wav。
