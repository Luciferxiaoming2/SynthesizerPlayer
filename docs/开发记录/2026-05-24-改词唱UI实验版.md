# 2026-05-24 改词唱 UI 实验版

## 本次目标

- 将“改词唱”从纯命令行/后端适配层推进到用户可在界面中触发的实验版。
- 不引入重型真实唱声模型，先复用 `PreviewSingingClient` 打通交互、后台任务、音频替换和试听链路。
- 保持真实模型后端可替换：后续可以继续接 DiffSinger/OpenVPI/RVC 等外部命令或本地模型。

## 已完成

- QML 歌词列表支持双击任意歌词行打开“实验版改词唱”弹窗。
- 弹窗显示原歌词，可输入新歌词，并提供“生成试听”和“恢复原唱”按钮。
- 新增 `LyricRewriteWorker` 后台任务，生成时显示进度，不阻塞主界面。
- 生成流程会按选中歌词的时间范围创建改唱片段，并替换当前人声音轨中的对应片段。
- 生成完成后自动把预览人声加载到播放器，用户点击播放即可试听改词唱效果。
- 新增桥接属性：`lyricRewriteBusy`、`lyricRewriteProgress`、`lyricRewriteStatus`、`lyricRewritePreviewPath`。
- 新增测试覆盖 UI 桥接层的改词唱预览生成。

## 当前限制

- 当前仍是 preview 合成，音色和真实唱法不是最终效果，只用于验证“选句、改词、生成、替换、试听”完整链路。
- 还没有打包真实 DiffSinger/OpenVPI/RVC 模型。
- 当前替换的是整句时间片段，尚未做音素级/字级对齐。
- 恢复原唱通过重新加载当前歌曲工程实现；后续可增加“多版本预览列表”和“应用到导出工程”。

## 继续推进：外部后端配置

- 新增 `core_engine/ai_singer/backend_config.py`，支持读取 `ai_singer_backend.json` 或 `plugins/config/ai_singer_backend.json`。
- 默认无配置时仍使用 `preview`，不要求用户下载模型。
- 配置 `backend=external` 时，可通过 `diff_command` 接入外部唱声合成命令；可选 `rvc_model_path` 和 `rvc_command` 接入音色转换。
- 改词唱生成完成后会写出同名 `.json` manifest，记录歌词行、时间范围、后端类型、试听文件和片段文件，便于后续做多版本管理或排查问题。
- 配置说明见 `docs/runbooks/ai_singer_backend.md`。

## 继续推进：歌词同步写回

- 改词唱生成成功后，会自动更新当前 `.lrc` 或 `.srt` 中对应歌词行。
- 首次改词会在同目录生成原歌词备份，例如 `lyrics.original.lrc`，便于用户回退。
- 播放器会重新加载歌词时间轴，滚动歌词显示会立即变成新歌词。
- 已新增 LRC/SRT 文本替换测试，并覆盖 UI 桥接层生成改词唱后的歌词写回。

## 继续推进：恢复一致性

- “恢复原唱”现在会优先恢复改词唱前的人声音轨，而不是只重新加载歌曲。
- 如果存在 `lyrics.original.lrc` / `lyrics.original.srt`，恢复时会同步写回原歌词并刷新滚动歌词。
- 恢复后会清空当前改词唱预览路径、manifest 路径和进度状态，避免用户误以为仍在使用上一版试听。

## 继续推进：重启后保持改词唱状态

- 改词唱生成成功后，会向歌曲工程 `project.json` 写入 `active_vocal_path`，记录当前启用的改词唱人声音轨。
- 歌曲库扫描现在会优先读取 `project.json` 中的 `vocal_path`、`instrumental_path` 和 `active_vocal_path`，不再只靠顶层文件名猜测。
- 重新启动应用或重新扫描 `save` 后，如果工程有启用的改词唱人声，会继续加载该版本，避免“歌词已改但声音回到原唱”的不一致。
- “恢复原唱”会清除 `active_vocal_path`，回到原始 `stems/vocal.wav`。

## 继续推进：右侧音高/电平监视器动态化

- 右侧柱形监视器不再使用静态假数据，改为根据当前播放位置附近的人声音轨能量实时计算。
- 播放推进时 `playbackChanged` 会刷新 `f0MonitorLevels`，QML 柱形高度随当前人声片段波动。
- 当前仍不是严格 F0 曲线，只是轻量电平/音高状态预览；真实 F0 后续可评估 `librosa.pyin`、CREPE 或 SwiftF0。

## 继续推进：aubio F0 可选后端

- 直接安装官方 `aubio==0.4.9` 在 Windows/Python 3.11 下会缺少 `aubio-generated.h`，不稳定。
- 已验证 `aubio-ledfx==0.4.11` 可以在当前 `uv` 环境中以预编译 wheel 安装，并提供兼容的 `aubio.pitch` API。
- `pyproject.toml` 新增 `f0` 可选依赖：`aubio-ledfx>=0.4.11`。
- UI 监视器现在优先使用 `aubio.pitch("yinfft")` 估算当前人声音轨片段的 F0；如果未安装 aubio 或检测失败，会自动回退到能量波动。
