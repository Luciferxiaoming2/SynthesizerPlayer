# 2026-05-25 跑调后台处理与双人声残留修复

> 当前标记：这是目前项目里的跑调最优版。此前“真实跑调 F0 管线第一版”“跑调功能增强与播放接入”“跑调爆音与歌词生成提示”“改词唱暂停与跑调修复”中的跑调结论均已被本版本取代，只作为历史过程保留。

> 追加修订：`2026-05-25 跑调句尾回音与多语言适配` 在本版本基础上补强了句尾原唱回音抑制，并扩展歌词行内进度的多语言分词。

## 背景

用户反馈跑调调大后仍像有两个人在唱，且原唱声音会压过跑调声音；拖动跑调后界面中间会卡住，容易误以为应用崩溃。

## 本次推进

- 跑调渲染改为 UI 后台任务：
  - 拖动跑调程度后不再在主线程同步重算整首歌。
  - QML 暴露 `toneDeafBusy`、`toneDeafProgress`、`toneDeafStatus`。
  - 右侧 F0 面板和底部跑调控制卡片显示加载中进度条。
  - 如果用户在处理过程中继续拖动，完成当前处理后自动应用最后一次选择的强度。
- 伴奏残留原唱处理加强：
  - 对高跑调强度放宽频域残留抑制触发条件。
  - 加强 vocal active 频段处理，减少 Demucs 伴奏 stem 中未跑调原声漏出。
  - 保留 Rubber Band `--formant` 高质量路径，优先保证人声音色不要明显变薄或机械化。

## 验收口径

- 文档和后续开发以本版本作为跑调功能的当前基线。
- 用户侧试听以便携版 `release/AudioForgePortable_next/audio-forge-ui.exe` 中的跑调效果为准。
- 旧版本中“第一版”“增强版”“爆音修复版”的跑调标记不再作为当前完成度判断。

## 当前边界

- 跑调仍依赖离线缓冲替换，不是逐 sample 实时算法；首次应用某个强度仍需要等待处理完成。
- “双人声”如果来自原始歌曲本身的和声或 Demucs 分离极差，软件只能尽量压低残留，不能百分百消除。
- 需要继续用真实歌曲人工试听，确认加强后的残留抑制不会过度削弱伴奏。
