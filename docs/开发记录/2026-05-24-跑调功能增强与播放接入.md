# 2026-05-24 跑调功能增强与播放接入

> 历史记录：本页跑调标记已被 `2026-05-25 跑调后台处理与双人声残留修复` 取代。当前验收请以 2026-05-25 的“跑调最优版”为准。

## 背景

用户反馈“跑调功能像是未完成，或者完成得不明显”。检查后发现原先跑调处理主要在导出链路中生效，UI 播放时没有明确接入；同时漂移上限偏保守，真实歌曲里听感可能不够明显。

## 本次推进

- 增强 `core_engine.dsp.tone_deaf`：
  - 跑调强度范围扩展到 `0.0-1.0`。
  - 最大音高漂移上限提升到 720 cents。
  - 增加短语级“唱错音”跳变和轻微颤动，让效果更容易听出来。
  - 有 F0 的片段至少保留一定权重，避免真实人声置信度偏低时跑调几乎不生效。
- 播放链路接入跑调：
  - UI 加载音频时会按当前“跑调强度”渲染人声音轨。
  - 拖动“跑调强度”后会重新处理当前播放缓冲，播放和导出保持一致。
  - 播放中拖动滑杆会原地替换播放引擎的人声缓冲，不再断开音频输出，下一批播放块即可听到新效果。
- 修复跑调缓存键：
  - 缓存增加人声指纹，避免两首同长度/同采样率歌曲误用旧渲染结果。
- CLI 文案改为中文，并同步 `--ratio` 范围说明。

## 开源库评估

- 项目已有 `librosa` 依赖，官方提供 `librosa.effects.pitch_shift`，但当前本机环境导入该模块时触发 numba 缓存定位错误。
- 为保证 PyInstaller 便携包稳定，本次不把 `librosa.effects.pitch_shift` 放入主链路；继续使用项目内轻量实现，并增强到可交付效果。
