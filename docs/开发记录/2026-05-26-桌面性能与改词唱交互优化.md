# 2026-05-26 桌面性能与改词唱交互优化

## 背景

当前应用在启动、导入完成刷新曲库、频繁切歌和 AI 改词唱交互时仍可能出现卡顿。右侧 AI 智能改唱工作舱内容较多，在窗口高度不足时，“启动智能补唱”按钮容易被挤出可视区域，用户会误以为按钮消失。

## 本次已完成

- [x] 将启动时的 `save/` 曲库扫描从 GUI 初始化路径移出，改为 `QThread` 后台扫描，避免首屏被同步扫描拖住。
- [x] 导入歌曲完成后先把新歌插入左侧列表，再后台刷新曲库，避免导入结束瞬间重新扫描导致卡顿。
- [x] 右侧 AI 智能改唱工作舱增加底部固定操作区，“启动智能补唱”按钮始终可见。
- [x] 改词唱生成完成后不再自动退出右侧工作舱，方便用户继续重置、再次修改或查看试听版本。
- [x] 增加纯本地硬件画像：启动时检测 CPU 线程数、Windows 物理内存、NVIDIA/CUDA 可用性。
- [x] 在设置、真实分离导入和 ACE 改词唱区域显示本机性能提示，低配设备不禁用功能，但明确提示耗时和内存风险。
- [x] faster-whisper 歌词识别按本机 CPU 动态限制线程数，避免在轻薄本上跑满 CPU 导致界面卡顿。
- [x] 真实分离导入前增加可用内存熔断：可用内存低于 500MB 时主动取消任务并提示用户。
- [x] ACE 模型启动改为后台预检：端口检查、已有接口检测、释放 7860 端口不再阻塞 GUI 主线程。
- [x] ACE 进程启动去掉 `waitForStarted` 阻塞等待，改为 `QProcess.started/errorOccurred/finished` 信号驱动。
- [x] 改词唱底部操作按钮固定显示“启动智能补唱”，模型未就绪时禁用但不再改成其它文案。
- [x] ACE 启动入口从 7860 Gradio 网页模式切换为官方 8001 REST API：应用现在执行 `uv run --no-sync acestep-api --host 127.0.0.1 --port 8001`，状态检测以 `/health`、`/openapi.json`、`/release_task`、`/query_result` 为准。
- [x] 仅检测到 7860 网页工作台时不再判定“模型已启动”，右侧按钮会继续允许启动 8001 API 服务，避免一直显示“模型启动中”或误走不可用接口。
- [x] ACE 启动日志写入 `user_data/logs/ace_startup.log`，后续若模型长时间卡住，可直接查看最后一段输出定位是环境同步、模型加载还是端口服务问题。
