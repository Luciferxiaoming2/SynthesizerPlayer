# 2026-05-26 桌面性能与改词唱交互优化

## 背景

当前应用在启动、导入完成刷新曲库、频繁切歌和 AI 改词唱交互时仍可能出现卡顿。右侧 AI 智能改唱工作舱内容较多，在窗口高度不足时，“启动智能补唱”按钮容易被挤出可视区域，用户会误以为按钮消失。

## 本次已完成

- [x] 将启动时的 `save/` 曲库扫描从 GUI 初始化路径移出，改为 `QThread` 后台扫描，避免首屏被同步扫描拖住。
- [x] 导入歌曲完成后先把新歌插入左侧列表，再后台刷新曲库，避免导入结束瞬间重新扫描导致卡顿。
- [x] 右侧 AI 智能改唱工作舱增加底部固定操作区，“启动智能补唱”按钮始终可见。
- [x] 改词唱生成完成后不再自动退出右侧工作舱，方便用户继续重置、再次修改或查看试听版本。

## 后续优化清单

- [ ] 拆分 `ui/main_window.py`：优先抽出歌曲库控制器、ACE 模型控制器、配置/日志服务和任务调度器。
- [ ] 建立全局 `TaskManager`：统一处理导入、分离、歌词、跑调、改词唱、导出等任务的互斥、取消和进度汇总。
- [ ] 懒加载重型依赖：避免启动阶段加载 torch、librosa、Whisper、ACE 等重依赖。
- [ ] 长音频流式处理：导出、跑调和混音逐步从整首读入内存改为 chunk 处理。
- [ ] 曲库分页/懒加载：当 `save/` 中歌曲很多时，只先显示最近歌曲，其它歌曲后台分页补充。
- [ ] 交付动静分离：主程序保持轻量，ffmpeg、rubberband、Demucs、ACE-Step 和模型包作为独立资源包或安装器步骤。
