# 2026-05-26 右栏改词唱滚动与 ACE 启动状态修复

## 问题

- 右侧「AI 智能改唱工作舱」内容较多，窗口高度不足时会把「启动智能改唱并修补」按钮顶到面板外。
- ACE 模型已经启动完成时，如果日志关键字没有被及时捕获，右侧按钮可能仍显示「模型启动中」。

## 修改

- 将右侧改词唱工作舱内容放入 `ScrollView`，保留面板宽度，内容超出时只在右栏内部滚动。
- 保留「返回」「启动 ACE 模型」「停止模型」「启动智能改唱并修补」「重置原词」等操作在同一工作舱中，不再被底部裁掉。
- 为 ACE 启动流程增加 2.5 秒一次的轻量状态轮询，启动中持续检测 `/health` 与 `/config`。
- 当自动接口可用时，立即把启动状态收尾到 100%，按钮文案变为「模型已启动」。
- 当 ACE 工作台 `/config` 已可访问但自动接口 `/health` 暂未确认时，也结束「模型启动中」，避免用户看到模型已经打开但应用仍无限加载。
- 桌面端改词唱入口改为只使用 ACE-Step：未检测到 ACE 自动接口时直接提示先启动 ACE，不再回退到本机轻量改词唱。
- 应用退出时会停止音频输出并自动停止 ACE 进程，同时清理 7860 端口上的 ACE 服务。
- ACE API 就绪检测从单一 `/health` 扩展为 `/health` + `/openapi.json` 路由确认，避免 CPU 高负载或健康检查短暂超时时误判为未启动。

## 验收

- 右栏内容高度不足时出现内部滚动条，智能补唱按钮可访问。
- ACE API 就绪后 `aceStartupBusy=false`、`aceStartupProgress=100`、`aceApiReady=true`。
- ACE 工作台就绪但 API 未确认时，启动状态同样收尾，状态提示改为「工作台已启动，自动接口正在确认」。
- 桌面端 ACE API 未就绪时不会生成本机轻量改词唱试听。
- `/health` 暂不可用但 `/openapi.json` 包含 `/release_task` 与 `/query_result` 时，应用仍会识别为 ACE API 可用。
- 新增单元测试覆盖启动轮询就绪状态。
